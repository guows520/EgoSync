# Sprint Plan：手机伴侣（Android）基建——配对加密连接、实时视图与离线降级（Epic 12～14 增量）

> **增量声明**：本计划为既有 sprint 体系的**纯增量扩充**，仅覆盖 epics.md 2026-08-26 追加段「手机伴侣（Android）基建」的 Story 12.1～14.2（3 Epic / 9 Story）。不触动 Epic 1～11 的任何既有条目与状态；历史 sprint-plan 文件保持不动。既有桌面 services（Epic 1～11 产物）是本增量的既有依赖，视为已在位。

## 1. Sprint 目标与成功标准

本 Sprint 仅交付以下范围（9 个 Story，按架构 Implementation Sequence 强排序）：

1. **Epic 12 手机伴侣配对与加密连接**：12.1 companion-proto 协议 crate / 12.2 桌面配对与连接服务 / 12.3 relay-server 无状态中继 / 12.4 Android 扫码配对与三态连接换装
2. **Epic 13 手机实时视图与远程操作**：13.1 桌面快照引擎与状态主动推送 / 13.2 手机实时快照视图换装 / 13.3 指令通道与流式对话
3. **Epic 14 离线降级、速记与通知**：14.1 降级态与速记排队 / 14.2 应用内通知与 NotificationDispatch 接口预留

Sprint 成功需同时满足：

- 9 个 Story 的验收条件（epics.md 增量段为唯一事实源）均有实现与自动化测试证据。
- snow↔noise-java 跨语言加密互通在 Story 12.1 内经黄金向量双向验证出清，参数套件 `Noise_XX_25519_ChaChaPoly_BLAKE2s` 冻结进 schema.json。
- 手机↔桌面建立端到端加密通道：直连/中继/离线三态可见，中继零知识（不可读明文、零落地、重启即清空）。
- 手机各屏由 mock 数据换装为真实数据（快照 + 指令通道），逐屏截图与 companion-android 原型零回归（UI 零重做是验收硬条件，UX-M1/M3）。
- 桌面零回归（NFR-M4）：现有 services 对伴侣一无所知，`npm run test:all` 全绿。
- FR-43 离线诚实可用：降级态 + 截止时间标注 + 幂等速记队列无丢失；14.2 仅冻结 NotificationDispatch 接口，**无任何推送实现**。

## 2. 明确排除范围

- 不纳入 12.1～14.2 以外的任何 Story；不改动 Epic 1～11 的追踪状态。
- **不实现任何移动推送**：FR-42 已 DEFERRED（决策 #18）。14.2 是接口预留薄故事——不实现系统推送、锁屏操作、FCM 集成、UnifiedPush 集成、中继离线投递；NotificationDispatch 仅冻结接口签名（V1 唯一实装 InAppAdapter）。
- **不做任何移动端 UI 重做**：companion-android/ 已是高保真原型，移动端 Story 一律为「装配缝换装真实实现」（`ConnectionClient` 接口签名不变、`SnapshotStore` 帧驱动、`AppModelContainer` 唯一换装点）；禁止重新设计样式与交互。
- 不在快照通道承载记忆内容（UX-M5 防呆）：记忆走指令通道现查现显；移动端不引入 Room。
- 不重复实现桌面既有能力：对话、任务、建议确认、记忆查询等由 `companion_dispatch` 调用既有 services 完成，不建第二套业务链路；不绕过 dispatch 直调 agent_bridge/opencode/DB。
- 不建仓库根 Cargo workspace（协议 crate 以 path 依赖方式被桌面与中继共享）。
- 历史遗留的桌面范围事项（如 Story 8.2/8.6 收尾、Epic 3/8/10/11 retrospective）不并入本计划。

## 4. 推荐实施顺序

强顺序链（架构 Implementation Sequence，不可重排）：

```
12.1 → {12.2, 12.3}（可并行）→ 12.4 → 13.1 → 13.2 → 13.3 → 14.1 → 14.2
```

### 单开发者默认顺序

1. **Story 12.1** — 风险出清点：协议 crate 冻结 8 种帧 schema + Noise XX 参数套件 + snow↔noise-java 黄金向量互验。跨语言加密互通是本增量最大技术风险，必须最先出清；此后三端只依赖同一份协议事实源。
2. **Story 12.2** — 桌面配对与连接服务（QR 生成、Noise XX 握手编排、NSD 广播、WS 监听、连接状态机、paired_devices 持久化）。12.4 之前手机侧以协议 crate 测试客户端模拟。
3. **Story 12.3** — relay-server 无状态中继与 Docker 部署（可与 12.2 交错进行，互不依赖）。
4. **Story 12.4** — Android 扫码配对与三态连接换装（依赖 12.2+12.3 齐备；noise-java 与 12.1 黄金向量互验，Keystore 私钥，NSD 发现 + 直连/中继双承载 + prefer-direct 滞回 + 指数退避）。
5. **Story 13.1 → 13.2 → 13.3** — 快照引擎与推送 → 手机快照视图换装 → 指令通道与流式对话（13.x 依赖 12.4 已建立的真实连接）。
6. **Story 14.1 → 14.2** — 降级态与速记排队（复用 13.3 幂等机制）→ 应用内通知与接口预留。

### 多开发者并行方案

- 12.2 与 12.3 可并行（前者桌面 Rust services，后者独立 relay-server 子项目，代码无交集；均仅依赖 12.1）。
- 12.4 不可与 12.2/12.3 并行开工（依赖两者完整交付）；13.2 可在 13.1 冻结帧语义后与其余桌面工作有限并行，但 13.3 必须等 13.2 的 StateMerger/取数接口稳定。
- 14.1 与 14.2 无相互依赖，可在 13.3 完成后并行。

## 9. 推荐第一个 Create Story 目标

**推荐：Story 12.1「companion-proto 协议 crate——帧 schema 冻结与跨语言加密互通」**（story key：`12-1-companion-proto-crate-frame-schema-and-interop`）。

理由：

1. Readiness 报告确认其立即可做、不受任何遗留项影响，且无前向依赖。
2. 它是全增量的风险出清点：跨语言 Noise 互通是最大技术不确定性，黄金向量双向验证在此 Story 内闭环，失败成本被隔离在最小范围。
3. 其产物（schema.json + 冻结参数套件 + 黄金向量 fixtures）是 12.2/12.3/12.4 三方的共同契约，先冻结可避免三端返工。
4. 相比 12.2（多层桌面增量）与 12.4（大体量换装），进入条件最少、尺寸最可控。

Create Story 12.1 时，应把「不建仓库根 workspace」「crypto.rs 全仓唯一 snow 依赖点」「noise-java 向量开发期手动产出、随测试提交」「帧明文与密钥材料零入日志」写入开发者约束。
