## 2. What Went Well

### 2.1 异步分类 + 事件通知模式

3-3 的 `task_create` 立即返回默认 Q2，后台 LLM 分类完成后通过 `task:classified` 事件更新前端。这个模式把 LLM 延迟从用户路径中移除，后续 Epic 4 的主动建议生成可复用此模式。

### 2.2 `updated_at` 不刷新策略

3-5 中设置 `at_risk` 时刻意不刷新 `updated_at`，避免状态闪烁。这是精准的边界条件识别 — 如果刷新了，下次循环会立即清除 `at_risk`，导致状态永远闪烁。

### 2.3 "完成释放名额"行为设计

3-4 中完成 Big Rock 自动清除标记，不恢复。这鼓励用户真正完成重要任务，而不是囤积 Big Rock 标签，符合柯维"大石头优先"的本意。

### 2.4 四象限分组 UX

3-6 把任务管理从"列表"升级为"决策工具"：固定渲染四个象限、空态鼓励语、配色区分、折叠动画。3-5 的 `at_risk` 琥珀色警告也很直觉。

### 2.5 100% 交付率

连续两个 Epic（Epic 2 和 Epic 3）全量交付，没有裁剪范围。

## 3. Challenges and Friction

### 3.1 边界条件/幂等性依赖 review 补救

3/7 stories 在 review 阶段才发现边界/幂等性问题：
- 3-1：删除确认缺失
- 3-2：完成切换非幂等 + 重复 ID 处理
- 3-3：手动覆盖逻辑错误

影响：虽然都在 patch 中修复，但如果 review 不够仔细，这些问题会溜进 done。

### 3.2 `protection_status` 裸字符串无枚举护栏

`'at_risk'` / `'normal'` 在 Rust db 层、commands 层、前端类型层和 `TasksTab` 组件多处以裸字符串出现，无 Rust 端共享常量或枚举护栏，拼写漂移不会被编译期捕获。Epic 4 的 4-6 直接建立其上，风险放大。

### 3.3 后台任务无优雅关闭

3-3 和 3-5 各有一个 `spawn_hourly_watch` 循环，无取消/关闭钩子，应用退出时随进程结束。Epic 4 的 4-1 后台调度器会引入更多定时任务，此模式需统一治理。

### 3.4 可访问性缺失

3-2 拖拽排序缺 `aria-live`，3-6 折叠区域需验证 `inert`/`aria-expanded`。均 defer 到 Epic 8 WCAG 审计。

### 3.5 前端测试 flaky

`ButlerSettingsContent.test.tsx` 全量 `vitest run` 下失败，单独运行 11/11 通过。测试隔离/异步竞态导致，与 story 3-6 diff 无因果，但使全量测试声明不可复现。

### 3.6 LLM prompt 缺日期

3-3 的 LLM prompt 缺少当前日期，review 才发现。意味着第一次实现的分类结果可能基于错误的日期上下文。

## 4. Key Learnings

1. **异步事件模式是 LLM 集成的有效范式。** `task_create` 立即返回 + 后台分类 + 事件更新，可复用于 Epic 4 的主动建议生成。
2. **边界条件需要前置而非依赖 review。** 3/7 stories 在 review 才补边界问题，需引入初始审查清单。
3. **后台任务和状态字面量是 Epic 4 的两个前置项。** 不处理会在 4-1 和 4-6 放大风险。
4. **LLM prompt 工程需要更强的初始审查。** 缺日期问题表明 prompt 提交前需有检查清单。
5. **LLM 降级链路完整但需关注 Q2 堆积。** 失败时 Q2 + 低置信度 + 不确定标记链路通畅，但连续失败会导致 Q2 视觉膨胀。
