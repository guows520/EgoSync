## 01｜传统 AI 只有一个聊天框，EgoSync 为什么要建立一支“角色团队”？

多数 AI 助手把人当成一个统一的问题来源：写方案、做计划、聊家庭，都发生在同一个上下文里。但真实的人同时是产品经理、父母、学习者，也可能是创作者。不同身份有不同目标、任务和判断标准。

EgoSync 把这些身份建模为可切换的角色工作区。每个角色可以拥有自己的配置、对话、任务、记忆和主动性级别；侧边栏则让用户在管家与不同角色之间切换。它不是给同一个聊天框换几套提示词，而是在尝试保存不同生活领域的长期上下文。

这带来的变化是：你不必每次从头解释“我现在以什么身份思考”。AI 的协作单位开始从一次对话，变成一个持续存在的角色。

**当前版本边界：**角色的定时工作循环只在 EgoSync 应用运行期间执行，不应描述为关机后仍全天候工作的后台服务。

> **截图占位符 01**：应用主界面全景；左侧同时显示“管家”和至少 3 个角色，当前角色有明显主题色。避免包含真实姓名和隐私任务。

## 02｜管家不是另一个万能 AI，而是你与多个角色之间的协调层

角色变多之后，会出现一个新问题：谁来提供全局视角？EgoSync 的答案是“管家”。

角色适合深入某个领域，管家则汇总跨角色信息，并承载简报、提醒、设置与全局入口。当前代码中，管家拥有独立视图和对话上下文，也能读取使命宣言等全局信息。用户仍然可以进入具体角色，处理领域内的对话、任务和记忆。

这种结构和“一个超级提示词包打天下”不同：专业上下文留在角色中，全局节奏留给管家。它更像组织中的协调者，而不是假装精通一切的全能人格。

**当前版本边界：**跨角色冲突检测和三步仲裁界面尚未实现；管家可以汇总信息，但不能宣传为已经能够自动解决所有角色冲突。

> **截图占位符 02**：管家工作区，画面中包含全局摘要或行动卡片；另配一张角色工作区形成对照。

## 03｜角色不是预设出来的：EgoSync 如何通过对话完成 Onboarding

传统产品常用长表单收集职业、目标和偏好。EgoSync 更希望通过自然对话识别用户反复提到的责任、关注点与身份，再让用户确认是否创建相应角色。

当前应用已经具备独立的 Onboarding 视图与角色确认弹窗。这个设计的重要之处，不是“AI 替你定义自己”，而是把角色发现变成一次共同澄清：系统提出理解，用户负责确认、修正或拒绝。

这样创建出的角色，更接近用户当下真实承担的生活领域，也为后续的任务、记忆和主动建议建立了归属边界。

**当前版本边界：**应使用“辅助识别和确认角色”，不要写成系统能够完整理解人格，或自动形成成熟的个人认知图谱。

> **截图占位符 03**：Onboarding 对话 + 角色确认弹窗；最好展示“建议角色—用户确认”的连续过程。

## 04｜当多个身份争夺时间：EgoSync 已经做到哪一步？

“产品经理”和“父亲”同时需要今晚的两个小时，AI 应该听谁的？这是个人 AI 迟早必须面对的问题。答案不应只是比较任务优先级，还应回到用户长期重视的价值。

EgoSync 当前已经实现使命宣言的读取、编辑、行为数据推断及管家上下文注入，也具备大石头规划和重要事项保护的基础。这让 AI 的建议不只依赖眼前一句话，而能参考用户明确表达的方向。

但必须诚实说明：跨角色时间冲突检测、三步仲裁流程、仲裁弹窗和自动“双赢方案”目前仍属于 V2 规划，并非已交付功能。这篇文章记录的是产品正在解决的问题，而不是完成声明。

> **截图占位符 04**：当前版本请截“使命宣言设置”或“大石头规划”；若使用冲突仲裁图，必须标注“概念示意 / V2 规划”，不能伪装成应用截图。

## 05｜AI 的记忆不该是黑箱：可查看来源，也可以选择遗忘

保存全部聊天记录，不等于拥有可用的长期记忆。EgoSync 会把对话中的信息提炼为结构化记忆，并按角色和类别组织。每条记忆还可以关联来源会话与原始消息。

在角色的记忆页，用户可以浏览不同类别的记忆、展开来源对话、查看原文，也可以主动点击“遗忘”并二次确认。这个设计把记忆控制权重新交给用户：AI 记住了什么，不应只能靠猜；不希望继续保留的内容，也应有清晰删除入口。

更准确的说法是“记忆来源可追踪”，而不是公开模型的隐藏思维链。

**当前版本边界：**删除记忆不应被宣传为已经自动清除所有可能的派生认知。

> **截图占位符 05**：记忆分类列表、展开后的来源对话，以及“遗忘”确认框，建议拼成三联图。

## 06｜从晨间简报到周复盘：AI 如何进入真实的行动节奏

好的个人 AI 不应只在被提问时出现。EgoSync 已经实现一套日常与每周节奏：晨间简报会汇总角色状态、今日截止任务、昨日记忆和未读提醒，并将生成结果写入管家对话；周规划帮助选择“大石头”，周复盘则重新审视进展。

这三者组成了一个简单闭环：早晨知道今天发生什么，一周开始时决定什么最重要，一周结束时检查方向与行动是否一致。AI 的价值因此不只是生成答案，而是减少用户反复整理上下文的成本。

**当前版本边界：**简报需要配置并依赖应用运行和模型服务；文章不应暗示系统在任何环境下都必然自动生成。

> **截图占位符 06B**：周规划/周复盘弹窗，展示“大石头”选择与复盘阶段。

## 07｜从“建议”到“行动卡片”：EgoSync 不只回答问题

聊天回答经常停在“你可以这样做”。EgoSync 尝试继续向前一步：调度器会根据角色的主动性设置和时间配置检查上下文，建议生成服务则可创建带状态的建议。用户可以在行动卡片上接受或拒绝，再决定是否把建议转化为后续行动。

这里最重要的不是让 AI 擅自替用户做决定，而是形成一条可见链路：发现值得关注的事情，提出具体建议，等待用户确认，然后进入任务推进。建议具有 pending、accepted、rejected 等状态，因此反馈不会完全消失在聊天文本里。

**当前版本边界：**“主动建议”不等于无限自主执行；实际行为仍受角色主动性、权限配置、应用运行状态和用户确认机制约束。

> **截图占位符 07**：管家或角色中的行动卡片，至少展示一条建议以及“接受/拒绝”操作。

## 08｜AI 的主动性应该有刻度，而不是只有开和关

有人希望 AI 多提醒，有人只想在需要时调用。EgoSync 为角色提供 passive、moderate、proactive 三档主动性，并把通知进一步分为 whisper、tap、knock。不同重要程度的信息可以进入通知面板，必要时才升级为更明显的“敲门”。

这套设计承认一个事实：主动性并非越高越好。真正值得信任的助手，需要知道什么时候出现，也需要知道什么时候保持安静。用户还可以调整通知和敲门声音等设置，让干预强度与自己的工作方式匹配。

“帮助用户减少依赖”目前更适合作为产品原则，而不是已经被代码或数据证明的结果。

> **截图占位符 08B**：通知面板，展示 whisper/tap/knock 的视觉层级。

## 09｜真正能干活的 AI：Agent Loop、Skill 与 MCP 如何接到一起

普通聊天模型主要生成文本；要完成真实工作，还需要工具、权限和执行循环。EgoSync 后端已经包含 Agent 会话、Sidecar 生命周期、SSE 流式事件，以及 thinking、text、tool-call 等事件的处理链路。

在前端输入框中，用户可以通过 `@Skill` 搜索并选择当前作用域允许的技能；后端还提供 Skill Registry 与 MCP Server 管理能力。角色因此不仅拥有不同的提示上下文，也可以拥有不同的工具边界。

这是一种更务实的 Agent 架构：能力不是默认全部开放，而是经过配置、作用域和权限进入角色。可扩展性与可控性必须同时存在。

**当前版本边界：**不能把“具备 Agent 基础设施”扩大成“任何第三方工具都已稳定兼容”。

> **截图占位符 09A**：聊天输入框输入 `@` 后的 Skill 搜索列表。  
> **截图占位符 09B**：设置页中的 Skill 或 MCP Server 配置。

## 10｜本地优先不等于绝对离线：EgoSync 如何把数据控制权交还用户

个人 AI 会接触任务、关系、目标和长期记忆，因此数据控制不是附加选项。EgoSync 当前使用本地 SQLite 保存主要数据与对话，并提供 JSON、Markdown、SQLite 等导出路径，也实现了销毁全部数据的命令。模型 Provider、模型和连接测试则可以在设置中管理，密钥由专门的 Secret Store 处理。

这里应使用“本地优先”而不是“数据永不离开设备”：当用户选择云端模型时，请求所需上下文仍可能发送给对应 Provider。更可信的承诺不是制造绝对化口号，而是让用户知道数据存在哪里、如何迁移、如何删除，以及何时会调用外部模型。
