## 2. What Went Well

### 2.1 平台地基成型

Epic 1 把高保真前端原型推进成具备桌面运行、Rust 后端、IPC、数据库、测试链路和配置链路的产品地基。后续 Epic 不再需要从基础设施开始摸索。

### 2.2 架构边界逐步落地

实现过程基本遵守了前端 service、Tauri command、service、db/llm 分层边界。关键路径没有把数据库或 LLM 调用直接塞进前端组件。

### 2.3 安全边界提前建立

API Key 通过 keyring 管理，数据库只保存引用，不保存明文。这个决策提前消除了后续 LLM 配置和多 Provider 扩展中的安全返工风险。

### 2.4 组件拆分降低后续维护成本

`App.tsx` 从大体量单文件拆到域组件结构，后续 Epic 2 可以在角色、对话、记忆等域内推进，不需要继续在单文件里堆逻辑。

### 2.5 引导链路形成产品闭环

Story 1.8 完成了从首次打开、LLM 引导、角色提议、用户确认、角色写库到主视图切换的关键路径，符合 Epic 1 的核心目标。

## 3. Challenges and Friction

### 3.1 状态同步流程不可靠

`1-7-butler-first-streaming-conversation.md` 仍显示 `Status: ready-for-dev`，但 sprint-status 标记为 `done`。这说明 story 文件、执行记录和 sprint-status 之间缺少强约束同步。

影响：复盘、审计、后续 story 依赖判断会出现口径分歧。

### 3.2 LLM 工具调用边界复杂

Story 1.8 记录了多个引导相关问题：重复角色创建、tools 未调用、`tool_choice` 格式、step 3 中断等。说明 LLM Function Calling 不是普通 UI 接口，必须按状态机和事件协议来治理。

影响：Epic 2 的角色涌现、记忆提炼、推理溯源如果继续依赖 LLM 结构化输出，需要更强的契约和测试夹具。

### 3.3 验证层次不均衡

多数 story 有 `cargo test`、`npm run test:frontend`、`tsc --noEmit`、`clippy` 等记录，但真实 Tauri 窗口、真实 LLM、首次引导、视觉回归、流式行为仍以手动验证为主。

影响：后续改动可能通过单元测试，但破坏真实用户路径。

### 3.4 Deferred 项开始形成债务

已记录的 deferred 包括 CSP、Cargo 镜像 fallback、视觉回归确认、发布元信息、类型化完善、部分 token 迁移等。这些不是立即阻塞，但如果不归档追踪，会在 Epic 8 加固阶段集中爆发。

## 4. Key Learnings

1. **先建边界，再接能力是有效路径。** Tauri、DB、keyring、LLM Provider、Event 流式这些基础边界先成型，降低了后续功能接入成本。
2. **LLM 结构化输出必须被当作协议，而不是文本解析。** Function Calling、tool_choice、事件 payload、确认弹窗需要形成稳定状态机。
3. **文档状态是交付物的一部分。** sprint-status 与 story 文件不一致会直接影响团队对“完成”的判断。
4. **前端视觉原型拆分后，真实数据格式兼容很关键。** Story 1.9 中 mock Lucide icon 与真实 emoji icon 的桥接是典型例子。
5. **安全模型越早稳定越省成本。** keyring 和 api_key_ref 模式为后续多 Provider、多角色模型配置留下了正确边界。

## 8. Significant Discoveries

### 8.1 LLM 能力需要协议化治理

Epic 1 证明，LLM 不是单纯的后端 API。只要涉及 Function Calling、流式、状态步骤、角色提议，就必须有：

- 明确的状态机
- 事件 payload 契约
- 可测试的工具调用样例
- 用户确认边界
- 失败路径设计

这会直接影响 Epic 2 的角色涌现、记忆提炼和推理溯源设计。

### 8.2 Mock 数据和真实数据格式差异会扩散

Story 1.9 暴露了 mock 图标格式与真实角色格式的差异。Epic 2 会继续遇到类似问题：角色、对话、记忆、任务都需要前端 Display Model 或 adapter，不能让组件直接绑定后端原始结构。

### 8.3 “done” 需要包含文档同步

实现完成但 story 文件状态未更新，会让复盘和后续依赖判断失真。Epic 2 开始前需要把文档同步纳入完成定义。
