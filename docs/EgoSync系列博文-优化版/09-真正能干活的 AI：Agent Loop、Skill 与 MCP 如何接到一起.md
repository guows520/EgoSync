# 真正能干活的 AI：Agent Loop、Skill 与 MCP 如何接到一起

> EgoSync 系列博文·优化版 09  
> 核心痛点：AI 看起来什么都会，但真正执行时仍然要用户自己完成全部操作。

## “我可以帮你……”之后，为什么总是你自己做

你让 AI 帮忙处理一项工作。它给出了一份漂亮的步骤：先收集资料，再整理信息，然后发送邮件，最后更新任务状态。

问题是，步骤写完之后，资料还没有收集，邮件还没有发送，任务也没有更新。所谓“帮忙”，仍然停留在解释怎么做。

个人 AI 如果要进入真实工作，就不能只生成文字，还必须拥有工具接入、执行循环和明确权限。

## EgoSync 的 Agent 基础设施

EgoSync 的 Agent 相关代码包含 Agent 会话、Sidecar 生命周期、AgentBridge、SSE 流式响应，以及 thinking、text、tool-call 事件处理。用户可以看到 Agent 不是一次性吐出一段答案，而是在一个执行过程中持续产生状态和结果。

这种结构让模型有机会调用工具、接收工具结果，再决定下一步，而不是把所有工作压缩成一段看似完整的说明。

## Skill 让能力跟着场景走

在聊天输入框里输入 `@`，用户可以搜索并选择当前作用域内允许的 Skill。比如，工作角色可以选择发布检查 Skill，学习角色可以选择资料整理 Skill。

Skill Registry 和 MCP Server 管理能力，为工具扩展提供了基础；角色配置和作用域权限，则帮助决定哪些能力可以被使用。

这很关键：AI 不应该拥有一把默认打开的万能钥匙。它应该知道自己在当前角色里能做什么，也应该在需要更高权限时停下来请求确认。

## 用户真正想要的不是“自动”，而是“少做重复动作”

如果每一个工具调用都静默发生，用户可能会不安；如果每一步都要求用户重新搬运信息，AI 又没有节省多少时间。更好的体验是：AI 展示正在做什么、为什么要做，并在影响较大的动作前让用户确认。

EgoSync 正在把角色、Skill、MCP 和权限放进同一套协作结构中。

## 当前版本边界

当前实现证明 EgoSync 具备 Agent 执行基础、Skill 选择和 MCP 管理能力，但不能扩大为所有第三方工具都已稳定兼容，也不能宣称任何任务都可以自动完成。

## 结语

一个只会给建议的 AI 是问答工具；一个能够在边界清晰、过程可见、权限受控的前提下推进工作的 AI，才更接近真正的助手。

EgoSync 想把“会说”进一步变成“能协作完成”。
