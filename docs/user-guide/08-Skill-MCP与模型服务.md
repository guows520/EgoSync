# 8. Skill、MCP 与模型服务

本章面向希望扩展 Agent 能力的用户。普通用户可以先使用默认配置；只有在需要特定工作流或外部工具时，才需要深入设置。

## 8.1 Skill 是什么

Skill 是一组可复用的做事方法，通常描述：输入需要什么、应该按什么步骤处理、输出应是什么格式。

适合做成 Skill 的内容包括：

- 固定格式的会议纪要整理；
- 代码审查清单；
- 研究报告结构；
- 任务拆解模板；
- 某个领域的判断流程。

## 8.2 为管家或角色启用 Skill

### 管家 Skill

1. 打开管家视图的“设置”。
2. 找到 Skill 配置区域。
3. 开启默认元 Skill 或已导入的 Skill。
4. 保存并等待同步完成。

### 角色 Skill

1. 进入目标角色。
2. 打开“设置”。
3. 在 Skill 列表中勾选需要的 Skill。
4. 保存。

角色只能使用已绑定且启用的 Skill；角色之间的 Skill 配置相互独立。

## 8.3 导入自定义skill

1. 在角色或管家设置中选择导入自定义 Skill。
2. 选择包含 `SKILL.md` 的目录。
3. 预览 Skill 名称、描述和内容摘要。
4. 确认导入。
5. 选择使用范围：仅当前角色、多个角色或管家。
6. 启用该 Skill。

导入前检查来源是否可信。Skill 中的说明可能会影响 Agent 的行为，不要导入来源不明的文件。

## 8.4 发现并导入 opencode 生态 Skill

1. 打开对应范围的 Skill 设置。
2. 确认已启用用于发现 Skill 的能力。
3. 点击发现 opencode Skill。
4. 阅读候选项的名称、来源路径和摘要。
5. 对需要的 Skill 点击导入。
6. 导入完成后检查是否已自动启用。

如果发现结果为空，先确认：

- 发现能力已启用；
- opencode 目录可访问；
- 当前角色或管家的范围设置正确；
- 候选 Skill 没有因为重复或格式问题被跳过。

## 8.5 使用 `@Skill` 选择本轮能力

Skill 配置决定“可用范围”，而消息中的 `@Skill` 决定“本轮优先使用哪个”。两者不同：

- 未启用的 Skill 不会出现在候选菜单；
- 没有指定 `@Skill` 时，Agent 会按默认能力和任务内容判断；
- 指定后仍需确保输入与 Skill 的适用范围匹配。

## 8.6 MCP Server 是什么

MCP Server 为 Agent 提供外部工具或数据连接，例如本地命令、远程接口或特定数据源。

EgoSync 支持管理不同类型的 MCP Server，包括：

- SSE；
- Streamable HTTP；
- stdio 本地命令。

## 8.7 添加和测试 MCP Server

1. 打开左侧“设置” → “MCP Server”。
2. 点击添加。
3. 填写名称和服务类型。
4. 按类型填写 URL、命令、参数或环境变量。
5. 保存。
6. 使用测试入口验证连接。
7. 启用 Server。

远程 Server 要确认 URL、网络和认证信息；stdio Server 要确认本机命令可执行。


## 8.8 为角色绑定 MCP Server

角色使用 MCP Server 需要同时满足：

1. Server 本身处于启用状态；
2. Server 已绑定到该角色；
3. Agent 配置同步成功。

关闭 Server 时，绑定关系会保留；重新启用后，符合条件的绑定可以恢复生效。管家的 MCP 绑定与角色绑定相互独立。

## 8.9 模型服务与工具配置的关系

- 模型服务决定 Agent 使用哪个 LLM Provider；
- Skill 决定 Agent 采用哪套工作方法；
- MCP Server 决定 Agent 可以访问哪些外部工具；
- 权限设置决定工具调用的边界。

建议先确认模型服务可用，再逐个启用 Skill 和 MCP，避免一次引入过多变量。

## 8.10 工具权限与安全边界

Agent 可能具备读取、写入、编辑、执行命令或访问外部服务的能力。使用这些能力时：

- 只给当前任务需要的权限；
- 对写入文件、执行命令、发送外部请求等动作保持确认意识；
- 不要在不清楚影响范围时接受批量修改；
- 对来源不明的 Skill、MCP Server 和命令保持谨慎；
- 发现 Agent 的操作超出目标时，立即停止并重新描述边界。

Skill 和 MCP 的“可用”不等于“应该在每个任务中使用”，应根据任务最小化启用范围。
