# 10. 故障排查与术语

## 10.1 无法发送消息

按顺序检查：

1. 是否已经配置默认模型服务。
2. 模型服务的连接测试是否通过。
3. 当前网络是否可用（远程 Provider 需要网络）。
4. 是否误选了已删除或已禁用的 Skill。
5. 是否有正在生成的消息没有完成。
6. 关闭并重新打开当前对话后重试。

如果只有某个角色无法对话，检查该角色的模型、Skill、MCP 和权限配置；如果所有角色都无法对话，优先检查全局模型服务。

## 10.2 Skill 不出现在 `@` 菜单

- 确认 Skill 已导入；
- 确认 Skill 已绑定到当前管家或角色；
- 确认 Skill 处于启用状态；
- 确认当前输入框已经输入 `@`；
- 返回设置重新保存，等待注册表同步；
- 如果是自定义 Skill，检查目录中是否存在有效的 `SKILL.md`。

## 10.3 MCP Server 测试失败

### 远程类型

检查 URL、协议类型、认证信息和网络连接。

### stdio 类型

检查命令是否安装、路径是否正确、参数是否完整，以及当前用户是否有执行权限。

### 仍然失败时

先关闭该 Server，确认普通对话可用，再单独启用并测试，避免多个外部工具同时干扰定位。

## 10.4 任务没有被正确分类

- 把任务写成明确的结果，而不是模糊动作；
- 补充截止时间、影响范围和重要性；
- 在编辑任务中手动指定象限；
- 检查任务是否归属到了正确的角色；
- 对已经完成或不再重要的任务及时更新状态。

## 10.5 没有收到主动提醒

检查：

1. 角色主动性级别；
2. 调度时间是否启用；
3. 应用是否在计划时间可运行；
4. 是否存在满足提醒条件的任务；
5. 通知中心是否已有未读提醒；
6. 管家和角色是否处于正确的视图/范围。

主动提醒是基于任务、风险和调度条件生成的，不保证固定频率产生新内容。

## 10.6 数据导入后看不到角色或任务

1. 确认导入流程已完成且没有错误提示。
2. 重新打开应用。
3. 检查是否导入了正确的 JSON 或 SQLite 文件。
4. 检查筛选条件和归档角色区域。
5. 重新配置模型服务、Skill 和 MCP Server。

## 10.7 常用术语

| 术语 | 解释 |
| --- | --- |
| 管家 | EgoSync 的全局数字分身入口 |
| 角色 | 针对某个领域的专属 Agent |
| Agent | 能理解目标、组织步骤并使用工具完成工作的智能执行单元 |
| Skill | 描述特定工作方法的可复用能力包 |
| MCP Server | 为 Agent 提供外部工具或数据连接的服务 |
| 工作循环 | 角色按调度周期检查任务并生成主动建议的过程 |
| 大石头 | 本周最重要、需要优先保护的任务 |
| Q1/Q2/Q3/Q4 | 艾森豪威尔四象限中的四类任务 |
| 记忆 | 从对话中提炼、可被后续使用的结构化信息 |
| 敲门 | 三级通知中最高打扰级别的提醒 |
| 能量 | 用于辅助观察角色近期状态的指标 |

## 10.8 反馈问题时建议提供的信息

如果需要提交问题，请尽量提供：

- 操作路径，例如“管家 → 设置 → MCP Server”；
- 具体点击步骤；
- 页面上的错误提示；
- 是否只有一个角色受影响；
- 是否最近导入过数据、Skill 或 MCP；
- 问题发生的大致时间。

不要在反馈中直接粘贴 API Key、访问令牌或未经脱敏的敏感对话。
