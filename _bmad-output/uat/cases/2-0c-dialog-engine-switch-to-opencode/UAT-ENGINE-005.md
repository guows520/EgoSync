# UAT-ENGINE-005 管家建议新建角色时，必须经用户确认才会真正创建

## 业务场景
聊着聊着，管家觉得用户需要一个新分身（如"健身教练"），于是主动提议。这是个重要边界：管家只能"建议"，绝不能擅自替用户把角色创建落库——必须弹出确认框，用户点了"同意"才真正创建。

## 前置条件
- EgoSync 正常运行，高级引擎可用
- 通过对话能引导管家产生新角色建议（如表达出某个持续性需求）

## 测试步骤
1. 与管家对话，表达一个适合交给专门角色的持续需求，如"我最近想坚持健身，希望有人长期帮我盯计划"
2. 引导管家提出"是否创建一个健身教练角色"之类建议
3. 观察是否弹出角色创建确认弹窗（而不是直接就建好了）
4. 先点"取消/拒绝"，确认角色未被创建
5. 再次触发建议，点"同意"，确认角色这次被创建

## 预期结果
- 管家提议新角色时，前端弹出确认弹窗，主动权在用户手里
- 用户拒绝时，角色不会被创建，列表无变化
- 用户同意时，角色才被正式创建并出现在列表中
- 任何情况下都不存在"管家未经确认就把角色直接落库"的行为
