# 3. 对话、路由与 Agent 能力

## 3.1 如何向管家描述需求

管家更适合接收“目标”和“背景”，不要求你提前决定由谁处理。

推荐使用这个结构：

> 背景 + 想达成的结果 + 时间限制 + 已知约束 + 希望管家先做什么

例如：

> 下周要做产品评审，我有三份会议记录和一个初版方案。请先帮我找出风险，再把需要跟进的事项拆成任务。

管家会根据意图决定：直接回答、路由到某个角色、创建任务、调用工具，或先向你提问补充信息。

## 3.2 直接与角色对话

如果你已经知道应该由谁处理：

1. 点击左侧对应角色。
2. 在角色对话中说明问题。
3. 角色会结合自己的目标、个性、任务和记忆回答。

直接进入角色可以减少路由歧义，也能让对话上下文更聚焦。

## 3.3 管家委派给角色

当管家把任务交给角色时，对话中可能会显示委派记录或来源信息。你可以：

- 查看任务来自哪个角色；
- 点击来源跳转到角色对话；
- 在角色完成处理后回到管家继续统筹。

委派不是复制一份独立对话，而是保留“谁负责、为什么分配、结果是什么”的上下文。

## 3.4 在当前任务中指定 Skill

当你希望当前请求使用某个特定 Skill 时，在输入中使用 `@Skill`：

1. 在输入框中输入 `@`。
2. 从候选列表中选择已启用的 Skill。
3. 继续输入任务内容并发送。

示例：

> `@会议行动项提取` 请从下面的会议记录中提取负责人、截止时间和待办事项。

注意：

- 只能选择当前管家或角色已绑定且启用的 Skill。
- Skill 是本轮请求的明确偏好，不会自动修改其他角色的配置。
- 如果列表中没有目标 Skill，请先到角色或管家设置中启用它。

## 3.5 查看工具调用和推理来源

当 Agent 读取文件、执行命令、调用工具或使用 Skill 时，消息中会显示相应的操作记录。你可以用它判断：

- Agent 实际查看了哪些信息；
- 使用了哪种工具或 Skill；
- 哪些结论来自对话、文件或任务数据；
- 哪些部分只是推测。

如果你问“为什么这么判断”，管家或角色会尽量说明判断依据和过程。当信息不足时，系统应明确表达不确定性，而不是把猜测说成确定事实。

## 3.6 Markdown 表格与长内容

对话支持常见 Markdown 内容，包括标题、列表、代码块和 GFM 表格。处理长内容时可以要求：

- “先给结论，再给依据”；
- “用表格比较”；
- “把行动项列成任务清单”；
- “只保留能执行的下一步”。

## 3.7 主动建议卡片

管家可能在对话中展示建议卡片。建议卡片通常包含：建议标题、建议内容、来源角色和优先级。

你可以：

- **确认**：接受建议，必要时转为任务或继续执行。
- **拒绝**：不采纳当前建议，并可选择拒绝原因。
- **稍后处理**：暂不处理，保留后续提醒的可能。

确认前先检查建议的范围、来源和预计成本。主动建议不会绕过你的确认直接执行关键动作。

## 3.8 任务拆解建议

当你在对话中提出一个范围较大的目标时，管家可能生成任务拆解建议。建议通常会把目标拆成多个可执行步骤，并标注任务之间的关系。

1. 阅读拆解出的任务标题和顺序。
2. 删除不需要的步骤或修改任务描述。
3. 选择接受全部拆解，或只保留其中一部分。
4. 检查生成任务的归属、四象限和截止时间。
5. 确认后再把它们加入任务清单。

如果目标本身还不清楚，不要急着接受拆解；先让管家询问缺失信息，能减少无效任务。

## 3.9 对话异常时的最小检查

1. 确认已配置默认模型服务。
2. 检查消息是否仍在生成中。
3. 重试时补充明确目标和必要上下文。
4. 如果使用了 `@Skill`，确认该 Skill 仍处于启用状态。
5. 如果需要本地文件或外部服务，确认对应权限和 MCP Server 可用。

## 3.10 连续对话和会话上下文

同一管家或角色中的连续消息会保留会话上下文。为了让 Agent 更容易延续工作：

- 在同一项目或主题中尽量继续使用同一会话；
- 需要切换主题时明确说明“这是另一个任务”；
- 长时间后重新打开会话时，先让 Agent 总结当前状态；
- 涉及多个角色时，让管家负责统筹，避免在多个角色之间重复粘贴同一段背景。

如果要从一条消息跳转到另一个角色，使用来源跳转入口，以保留原始上下文。
