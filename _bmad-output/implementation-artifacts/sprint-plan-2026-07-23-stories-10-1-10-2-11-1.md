# Sprint Plan：Skill 指定、管家 MCP 绑定与跨 Agent 活动统计

## 1. Sprint 目标与成功标准

本 Sprint 仅交付以下范围：

1. **Story 10.1：为当前任务选择并使用指定 Skill**
2. **Story 10.2：为管家独立管理并恢复 MCP Server 绑定**
3. **Story 11.1：查看并筛选跨 Agent 活动统计**

Sprint 成功需同时满足：

- 三个 Story 的验收条件均有实现与自动化测试证据。
- `@Skill` 只显示当前 Agent 已添加且启用的 Skill，并由后端重新校验、按任务冻结快照和记录真实审计。
- 管家 MCP 有独立绑定；Runtime 有效集合严格等于“管家绑定 ∩ enabled Server”；关闭后保留绑定、重新启用后恢复。
- Dashboard 的任务、结构化记忆、会话、待处理任务四项统计支持 Agent 与时间组合筛选，采用统一口径和半开区间 `[from, to)`。
- 不新增第二套 Skill 执行引擎、MCP 管理器、Runtime 同步器或前端数据聚合链路。

## 2. 明确排除范围

- 不纳入任何其他 Story。
- **不重复实现**现有 MCP Server 查看、创建、编辑、删除、连接测试和 enabled 启停能力。
- 不重复实现现有角色 MCP 绑定、`AgentConfigService`、`OpencodeMcpScopeLock` 或 Runtime refresh 链路。
- 不把现有 MCP CRUD/测试/启停能力计为 Story 10.2 的新增交付；它们只进入集成与回归测试范围。
- 不新增 Skill 执行引擎；Story 10.1 复用 opencode 原生 Skill 执行和既有会话链路。
- 不由 React 直接访问或聚合主数据库、会话数据库或 opencode Runtime。

## 3. Readiness 条件与 Sprint 入口门槛

最新 Implementation Readiness Report（2026-07-23）结论为 **READY WITH CONDITIONS**。编码前必须在各 Create Story 文件中固定以下 UX 增量，不另建 Story：

- 10.1：`@Skill` 候选、键盘交互、空状态、失效提示与本轮选择展示。
- 10.2：Server enabled 与“已绑定给管家”的视觉区分，以及保存失败、Runtime 刷新失败、仅重试刷新等反馈。
- 11.1：Agent/时间筛选、加载时保留旧结果、空数据、请求失败和筛选回退反馈。

Story 10.2 必须采用下文的双阶段执行和检查点；否则不应进入开发。

## 4. 推荐实施顺序

### 单开发者默认顺序

1. **Story 10.1** — 最小且完整的垂直切片，先验证“可信 Agent 作用域 + 请求级能力快照 + Runtime 传递”模式。
2. **Story 11.1** — 与 MCP 配置链路耦合最低；在稳定的 Dashboard 聚合边界内完成统计与筛选。
3. **Story 10.2-A：管家 MCP 绑定与 Runtime 垂直链路** — 完成数据关系、绑定接口、管家 UI、作用域交集、配置投影、刷新和部分失败语义。
4. **Story 10.2-B：导入导出与旧数据兼容** — 仅在 10.2-A 检查点通过后实施。
5. **Sprint 集成回归** — 聚焦 Agent 隔离、Runtime 快照、MCP 既有能力无回归及 Dashboard 旧请求竞态。

### 多开发者并行方案

- 先创建 10.1，并固定三个 Story 的 UX 契约。
- **10.1 与 11.1 可并行**：前者主要触及对话/Skill/Runtime 传递，后者主要触及 Dashboard/Repository 聚合。
- **10.2-A 可与 11.1 并行**，但不建议与 10.1 的 Runtime/Agent 配置改动同时合并；先稳定 10.1 的请求快照与 Runtime 契约，以减少冲突。
- **10.2-B 不可与 10.2-A 并行**，因为导入导出格式和兼容逻辑依赖绑定模型、Repository 与 Service 契约稳定。
- 三条线最终在关键 E2E 与 Runtime 回归阶段汇合。

## 6. Story 10.2 强制检查点

### 检查点 A：数据与领域隔离

- Migration 只创建管家绑定所需最小关系。
- 旧数据库升级后管家绑定为空；角色绑定不复制、不修改、不合并。
- Repository/Service 的添加和移除保持幂等。

### 检查点 B：Runtime 垂直链路

- 管家有效 MCP 集合严格为“绑定集合 ∩ enabled 集合”。
- Server 关闭不删除管家或角色绑定；重新启用后原绑定恢复。
- 配置变化复用现有投影、锁与 refresh 链路；运行中任务保持启动快照。
- 区分“持久化失败”和“已保存但 Runtime 未刷新”，后者支持仅重试刷新。

### 检查点 C：数据主权与兼容

- enabled、管家绑定、角色绑定分别导出和恢复。
- 不导出 keyring 或环境变量中的明文秘密。
- 旧版本数据缺少管家绑定时兼容导入并初始化为空。

只有前一检查点的实现、测试和审查均通过，才能进入下一检查点。

## 7. 测试范围

### Story 10.1

- **Rust/Service/Command**：可信 Agent 身份解析、候选隔离、有效选择、选择后失效竞态、未指定兼容路径、任务级快照、失败前不进入 Runtime、审计真实性。
- **前端组件**：候选筛选、空状态、方向键/Enter/Escape、ARIA、普通消息兼容、下一消息不沿用选择。
- **关键 E2E**：管家与角色集合不串扰；显式 Skill 实际生效；禁用/移除后发送被拒绝；流式期间配置变化不改变当前任务。

### Story 11.1

- **Repository/Service/Command**：四项指标、会话按 session 去重、`pendingTaskCount <= taskCount`、Agent/时间组合筛选、RFC 3339 校验、`[from, to)` 边界、无效角色与无效范围拒绝、空数据为 0。
- **强制故障测试**：主库或会话库任一失败时整个请求失败，不返回真假混合结果。
- **Hook/组件**：默认“全部 Agent/全部时间”、失效角色回退、加载保留上次成功值、旧请求不得覆盖新结果。
- **关键 E2E**：组合筛选一致更新四项指标；现有角色卡片与排序无回归。

### Story 10.2

- **Migration/Repository/Service/Command**：绑定隔离、幂等、候选仅含 enabled 且未绑定 Server、作用域交集、关闭保留绑定、重启恢复、持久化失败、Runtime 部分失败与仅刷新重试。
- **导入导出**：三类状态分别恢复、旧数据兼容、秘密不导出。
- **组件/E2E**：enabled 与绑定状态清晰区分；管家操作不影响角色绑定；后续会话使用最新配置；运行中任务保持快照。
- **既有能力回归（非新增实现）**：MCP Server CRUD、连接测试和 enabled 启停仍可用，且状态变化不隐式修改任何绑定。

### Sprint 级验证

- Rust：目标模块单元/集成测试与 `cargo check`。
- 前端：目标组件/Hook 测试、TypeScript 严格编译和生产构建。
- E2E：仅覆盖三项新增用户旅程及与既有 MCP 能力的必要回归。
- 任一测试被跳过或环境缺失时，必须明确记录，不能宣称全部通过。

## 8. 主要风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 10.2 接近 Epic-sized，单次实现易漏层或超上下文 | 高 | 同一 Story 内强制拆为 A/B 阶段，设置三个检查点，逐层测试后再继续 |
| UX 增量规范缺失导致验收歧义 | 高 | Create Story 时先固定控件状态、错误、部分成功、刷新重试和竞态反馈 |
| 重复实现既有 MCP 能力造成双链路漂移 | 高 | 新增范围只允许管家绑定与投影扩展；CRUD/测试/启停只做复用和回归 |
| Skill 在选择后失效或配置在流式期间变化 | 中 | 后端发送前重验；执行启动时冻结请求快照；失败时不进入 Runtime |
| 跨数据库聚合返回部分真实数据 | 中 | 任一数据源失败则整个统计请求失败；禁止默认值伪装成功 |
| 快速筛选导致旧请求覆盖新结果 | 中 | Hook 使用请求序号/取消策略，仅最新请求可提交状态 |
| 10.1 与 10.2 同时修改 Runtime/Agent 配置边界产生冲突 | 中 | 10.1 契约先稳定；错开合并窗口；集成后执行 Runtime 回归 |
| Architecture 中 FR-39 过时 Gap 误导开发 | 低 | Create Story 引用 2026-07-23 PRD/Readiness 作为准绳，并标注该 Gap 已过时 |

## 9. 推荐第一个 Create Story 目标

**推荐：Story 10.1「为当前任务选择并使用指定 Skill」**。

理由：

1. Readiness 已确认其覆盖完整、架构一致且单 Agent 尺寸可控。
2. 它是最小的端到端垂直切片，能尽早验证可信 Agent 作用域、请求级快照、Runtime 传递和审计模式。
3. 其结果可降低后续 10.2 在 Runtime 配置与任务快照方面的设计风险。
4. 相比 10.2，进入条件更少；相比 11.1，更直接验证本 Sprint 最关键的“显式控制 Agent 能力”主线。

Create Story 10.1 时，应把 UX 增量状态、预计改动文件清单、分层测试命令和“不新增 Skill 执行引擎”写入开发者约束。
