# 真正能干活的 AI：Agent Loop、Skill 与 MCP 如何接到一起

> 系列：EgoSync 与传统 AI 助手的差异（9/10）  
> 状态：当前版本技术能力介绍  
> 关键词：Agent Loop、Sidecar、Skill、MCP、权限

## 从生成文字到完成工作，中间缺了什么

语言模型擅长理解和生成文本，但真实工作通常还需要读取信息、调用工具、执行动作、获得结果，再根据结果决定下一步。如果没有执行循环，AI 的“帮你完成”往往只是把操作步骤写成一段说明。

EgoSync 的 Agent 相关代码，已经具备一条较完整的执行基础：Agent 会话、Sidecar 生命周期、AgentBridge、SSE 流式响应，以及 thinking、text、tool-call 等事件处理。前端可以持续接收执行过程中的状态，后端则负责维持 Agent 与工具之间的连接。

## Skill 让能力变得可选择

在聊天输入框中，用户可以输入 `@`，搜索并选择当前作用域允许的 Skill。选中的 Skill 会随发送逻辑传递给 Agent。这个交互很重要，因为它让“这次对话需要什么能力”变成可见选择，而不是模型在后台随意猜测。

Skill Registry 负责管理技能，MCP Server 管理则提供了更广泛的工具接入入口。角色可以拥有不同的技能边界：一个角色可以连接项目工作流，另一个角色只使用整理和分析能力。

## 能力和权限必须一起设计

一个真正可执行的 Agent，越能做事，越需要清楚自己不能做什么。EgoSync 的 Agent 配置和 Skill 作用域权限，为这种边界提供了产品入口。用户可以在设置中管理 Agent 配置、Skill 和 MCP Server，而不是把所有工具默认开放给所有角色。

这也解释了 EgoSync 与普通聊天助手的差异：它不只关心“模型能不能回答”，还关心“哪个角色在什么权限下可以行动”。

## 一个具体场景

用户在工作角色中输入：“@发布检查，帮我检查今天发布前还缺哪些准备。”Agent 可以加载对应 Skill，流式返回文本、思考状态和工具调用过程，再把结果整理为可确认的行动建议。若某个动作需要更高权限，则应该停在确认或授权环节，而不是默认执行。

## 当前版本边界

当前代码提供 Agent 基础设施、Skill 选择和 MCP 管理能力，但不能扩大为“所有第三方工具都已稳定兼容”或“所有任务都可以自动完成”。具体可执行范围取决于实际配置、Provider、Skill、MCP Server 和权限。

## 结语

AI Agent 的竞争不只是模型参数的竞争，也包括执行循环、工具接入和权限边界的设计。EgoSync 正在把这些能力放进角色工作区，让“能做什么”与“谁可以做”同时变得可见。
