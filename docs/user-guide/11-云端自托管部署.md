# 11. 云端自托管部署

本章面向希望在自己的服务器（VPS / NAS / 家用主机）上运行 EgoSync 云端版的用户。云端版是**自托管单用户**形态：完整引擎（Rust server + opencode + 双 SQLite）与全部数据运行在你自己的服务器上，官方零持有、零中转、零落地你的数据；不需要安装桌面客户端，用浏览器即可使用全部功能。

部署形态一览：

| 形态 | 引擎 | 数据 | 适合 |
| --- | --- | --- | --- |
| 桌面版 | 本机 Tauri 应用 | 本机 SQLite | 日常主力 |
| 云端版（本章） | 服务器 Docker 容器 | 服务器 /data 卷 | 7×24 常驻、多设备浏览器访问 |

两个版本数据各自独立；从桌面迁移到云端见[「桌面 → 云端迁移」](#1110-桌面--云端迁移)一节。

## 11.1 你需要准备什么

- 一台服务器：**1 核 CPU / 1GB 内存**起步即可（资源预算实测见[ 11.7](#117-资源预算1c1g-实测)），系统任选（Linux 发行版均可）；
- 服务器安装 **Docker Engine（20.10+）与 Docker Compose v2**；
- 一个**域名**（解析到服务器公网 IP）——公网 HTTPS 由 Caddy 自动签发证书需要它；仅内网 / 本机试用可以跳过（用 `localhost` 或内网 IP，见 11.4 路径 A 说明）；
- 防火墙 / 安全组放行 **80 与 443** 端口（HTTP 证书验证 + HTTPS 访问都需要）。

## 11.2 从零到浏览器：完整步骤

以下命令都在仓库 `server/` 目录执行（先获取仓库代码：`git clone` 或下载源码包）。

### 第 1 步：域名解析

在你的域名服务商处添加 A 记录（AAAA 记录，IPv6 服务器）：

```
类型: A    主机记录: ego（或你喜欢的子域）   记录值: <服务器公网 IP>
```

等待解析生效（`ping ego.example.com` 返回服务器 IP 即可）。内网 / 本机演练可跳过，直接用 `localhost`。

### 第 2 步：创建 .env 配置文件

在 `server/` 目录创建 `.env` 文件（该文件包含密钥，**绝不能提交进 git**）：

```bash
cd server
cp /dev/null .env   # 或直接用编辑器创建
```

写入以下内容（最小可用配置）：

```ini
# 你的访问域名（公网填你的域名；本机演练填 localhost）
EGOSYNC_DOMAIN=ego.example.com

# 访问令牌（推荐预设：见 11.9「公网抢占窗口」——不想预设可留空，
# 走浏览器首访初始化向导）
EGOSYNC_TOKEN=一串足够长的随机令牌

# 时区（简报 / 周复盘的调度时间按此时区，默认 Asia/Shanghai）
# TZ=Asia/Shanghai

# 日志级别（默认 info）
# RUST_LOG=info
```

> **生成随机令牌**：`openssl rand -base64 24`，或任意密码管理器的随机密码（长度 ≥ 8，建议 20+）。

### 第 3 步：启动

```bash
docker compose up -d --build
```

首次构建需要拉取基础镜像、编译前后端并下载 opencode 引擎（约 5–20 分钟，取决于服务器性能与网络）。之后启动只需 `docker compose up -d`。

### 第 4 步：验证服务就绪

```bash
# 存活探针：返回 {"status":"ok"} 即服务已起来
curl -k https://ego.example.com/healthz

# 查看容器状态（两个服务都应为 Up / healthy）
docker compose ps

# 查看服务日志（JSON 结构化，一行一条事件）
docker compose logs -f egosync-server
```

`healthz` 返回 200 后，用浏览器打开 `https://ego.example.com` 即可进入登录页。

### 第 5 步：首访初始化与登录

- **预设置了 `EGOSYNC_TOKEN`**：直接在登录页输入该令牌登录；
- **未预设令牌**：首次打开页面会进入「初始化」向导，设置一个 ≥ 8 位的访问令牌（设置后向导永久关闭）——完整流程见[快速开始](./01-快速开始.md)与 README「Web 自托管服务」一节的首访说明。

登录后即进入与桌面版同构的完整界面（管家对话、角色、任务、记忆、仪表盘等全部可用）。浏览器会话是 30 天持久 Cookie——关闭浏览器重开免重登，侧栏提供登出入口。

### 第 6 步（推荐）：配置模型服务

云端版是全新实例，首次使用需要配置模型服务（API Key 等）：**设置 → 模型服务配置**，与桌面版操作一致（详见[第 8 章](./08-Skill-MCP与模型服务.md)）。从桌面版迁移的用户请阅读[ 11.10](#1110-桌面--云端迁移)：**LLM API Key 不随数据导出迁移，必须在云端重新录入一次**。

## 11.3 日常运维

```bash
docker compose ps          # 状态
docker compose logs -f     # 日志（跟随）
docker compose restart     # 重启（数据无损）
docker compose down        # 停止并移除容器（/data 卷保留）
```

**升级**（镜像未发布到任何 registry，`docker compose pull` 拉不到东西——CI 镜像发布是后续故事交付物）：

```bash
git pull                       # 拉取最新代码
docker compose up -d --build   # 重新构建并滚动替换（/data 卷无损）
```

**重启 / 服务器重启自愈**：两个服务都是 `restart: unless-stopped`——宿主机重启后 Docker 自动拉起；双 SQLite 库、`secrets.json`、Caddy 证书分属独立命名卷，重启零丢失。

**升级**是两步操作：拉取新代码（`git pull`）→ `docker compose up -d --build`。数据库迁移在启动时自动前滚（幂等）。

## 11.4 TLS 两条路径

全程 HTTPS 是硬性要求（明文 HTTP 访问会被永久重定向到 https——Caddy 发 308：与 301 同为永久重定向，且保留请求方法，POST 不会被降级为 GET）。有两种落地方式：

### 路径 A：内置 Caddy（默认，推荐）

默认的 `docker-compose.yml` 自带 `caddy` 服务，职责只有 TLS 终结 + 反向代理：

- **公网域名**：Caddy 经 ACME 自动申请并续期证书（Let's Encrypt / ZeroSSL），**无需任何证书操作**——只要 80/443 端口可达、域名解析正确，首次访问时证书就绪；
- **`localhost` / 内网 IP**：Caddy 使用**内部 CA 自签证书**，浏览器会提示「不安全」。本机演练可用 `curl -k` 跳过校验；要消除浏览器警告，从服务器导出 Caddy 根证书并导入系统/浏览器信任列表（`docker compose exec caddy cat /data/caddy/pki/authorities/local/root.crt`）。

### 路径 B：使用你自己的反向代理

已有 Nginx / Traefik / 云负载均衡的用户可以去掉 Caddy：

1. 编辑 `server/docker-compose.yml`，删除整个 `caddy` 服务块与 `caddy_data` / `caddy_config` 卷声明；
2. 给 `egosync-server` 服务追加端口映射（如 `ports: ["127.0.0.1:8080:8080"]`——绑定回环最安全，由本机反代转发）；
3. 在你的反代上配置 TLS 终结并转发到该端口。**自有反代必须满足以下要求**（缺一不可，均为 17.1 部署面冻结语义）：

| 要求 | 原因 |
| --- | --- |
| 转发 `X-Forwarded-Proto` 头（按入口协议回填 `https`/`http`） | server 侧 `EGOSYNC_BEHIND_PROXY=1` 时据此做同源判定与 Cookie Secure；Caddy 默认透传，Nginx 需 `proxy_set_header X-Forwarded-Proto $scheme` |
| **保持 `Host` 头原样转发**（Nginx 用 `proxy_set_header Host $http_host`——注意 `$host` 不含端口，非缺省端口部署如 `https://dom.com:8443` 会因 Origin 带 `:8443` 而 Host 变裸域名被同源判定拒绝） | 同源判定按 Host（含端口）比对 |
| 请求体上限 ≥ 50MB（或干脆不设） | 与 server 侧 body 上限 50MB 对齐，防代理层第二道暗限 |
| 响应**不做缓冲**、不设 write timeout | SSE 事件流逐写直达；chat 分钟级挂起是正常态，代理叠加短超时会掐断会话 |
| HTTP 明文访问重定向或拒绝 | 全程 TLS 纪律（Caddy 发 308 永久重定向，方法保留） |

> **HTTP/1.1 反代下的 SSE 连接数提示**：浏览器对同一域名（HTTP/1.1）最多开 6 个并发连接。EgoSync 的事件流（SSE）会占用其中 1 条长连接；同域页面若还加载其他 HTTP/1.1 长请求，可能触顶排队。启用 HTTP/2（HTTPS 下浏览器默认）即可解除该限制——Caddy 默认开启，无需操作；自有反代请确认开启 HTTP/2。

无论哪条路径，`EGOSYNC_BEHIND_PROXY=1` 都必须保持（compose 已默认设置）。它同时控制两件事：反代感知的同源判定（否则浏览器所有 POST 会被 403 拒绝）与 TLS 面 Cookie `Secure` 旗标。**未设该变量的 server 只按直连 HTTP 语义工作**（反代头一律忽略——这是防伪造的刻意设计）。

## 11.5 环境变量全表

`egosync-server` 认识的全部环境变量（compose 已为 Docker 形态预设合理默认）：

| 变量 | 语义 | 默认（compose 形态） |
| --- | --- | --- |
| `EGOSYNC_DATA_DIR` | 数据目录（双 SQLite 库 + `secrets.json` + opencode workspace） | `/data`（命名卷） |
| `EGOSYNC_HOST` | 监听地址 | `0.0.0.0`（容器内；不暴露宿主机） |
| `EGOSYNC_PORT` | 监听端口 | `8080` |
| `EGOSYNC_STATIC_DIR` | 前端静态目录 | `/app/static`（镜像内 dist） |
| `EGOSYNC_TOKEN` | 预置访问令牌（存在则首访向导关闭、登录按 env 常时比对） | 未设（走首访向导） |
| `EGOSYNC_BEHIND_PROXY` | 反代感知门控（`1`/`true` 开启）：同源判定读 `X-Forwarded-Proto`、TLS 面 Cookie 加 `Secure` | `1` |
| `EGOSYNC_OPENCODE_PATH` | opencode 二进制路径或其所在目录（文件取父目录；缺省按系统 PATH 解析） | `/app/resources/opencode`（镜像内） |
| `EGOSYNC_SECRET_{api_key_ref}` | LLM Key 的 env 引导通道（键名 = 前缀 + 引用名**原样区分大小写**拼接），见 11.6 | 未设 |
| `TZ` | 容器时区（调度判定基准） | `Asia/Shanghai` |
| `RUST_LOG` | 日志级别（`info` / `debug` …） | `info` |

## 11.6 密钥注入（LLM API Key）

云端版的密钥存储是**双通道、文件优先、env 兜底**：

- **主存储**：`/data/secrets.json`（权限 0600）。在网页「设置 → 模型服务配置」里保存 / 修改 Key 时写入这里——这是运行时唯一可写的事实源；
- **env 引导通道**：`EGOSYNC_SECRET_{api_key_ref}`。把 Key 放进 `.env`（compose 经 env_file 透传进容器），server 在文件里没有该 Key 时才会读它——适合「首启注入、页面重录持久化」的用法：
  ```ini
  # api_key_ref 在导出包的配置清单里（形如 llm_<uuid>_api_key，全小写）
  EGOSYNC_SECRET_llm_3f2a1b8c-xxxx-xxxx-xxxx-xxxxxxxxxxxx_api_key=sk-xxxx
  ```

安全边界（与 epic 冻结一致）：

- Key 只存在**服务端内存**与 `/data/secrets.json`（0600 明文——与 env 同级的安全边界，依赖文件系统权限）两处；
- 任何 API 响应不下发 Key（自动化测试断言 `llm_config_*` 响应无 `api_key` 键）；
- `secrets.json` / `*.db` 经 `.dockerignore` 拒于镜像层外，也**绝不进 git**；
- 某配置的 Key 缺失时，相关操作（连接测试、模型列表等）会返回统一的结构化错误并**指明重录路径**（设置 → 模型服务配置 → 编辑对应配置重新保存密钥）。

## 11.7 资源预算（1C1G 实测）

按 epic 预算（$5–10/月 VPS，1 核 1GB）实测（`docker stats --no-stream` 采样；引擎全量运行态——双 SQLite + opencode sidecar 已拉起，`/healthz?deep=1` 全绿后采样）：

| 指标 | 实测值 | 说明 |
| --- | --- | --- |
| egosync-server 常驻内存 | ~333 MB | 引擎双库 + opencode sidecar（bun 运行时） |
| caddy 常驻内存 | ~14 MB | TLS 终结 + 代理 |
| 合计 | ~347 MB | 1GB 内存预算内（系统占用量外仍余约 600MB） |

> 以上为本机演练环境（2C/3.6G，单用户空载）实测值，2026-09-21；生产请在自己的服务器上以同命令复核。空闲期 server 容器可低至 ~6 MB（无 sidecar 活动时），峰值出现在对话/工具执行中。

compose 已设 `mem_limit`（默认 768m，可用 `EGOSYNC_MEM_LIMIT` 调整）作为护栏。内存吃紧时优先保 egosync-server（caddy 占用很小）。

## 11.8 数据备份与恢复

数据全在 `egosync-data` 命名卷里（双 SQLite 库 + secrets.json + opencode workspace + 附件）。

**逻辑级备份**（应用内导出，运行中安全）：**云端版的应用内导入/导出入口与 `/api/export`、`/api/import` 端点是后续故事（17.3）的交付物**——当前云端 UI 中这些按钮按能力探测隐藏（桌面版可用，详见[第 9 章](./09-数据与隐私.md)）。在 17.3 交付之前，云端版请使用下方卷级备份。

**卷级备份**——**必须先停容器**：

```bash
docker compose stop                # 或 docker compose down（保留卷）
docker volume ls | grep egosync    # 核对卷名（见下方说明，防止拼写漂移）
docker run --rm -v egosync-server_egosync-data:/data -v $(pwd):/backup \
    alpine tar czf /backup/egosync-data-$(date +%F).tar.gz -C /data .
docker compose up -d
```

> **卷名为何是 `egosync-server_egosync-data`**：compose 文件已固定项目名（顶层 `name: egosync-server`），命名卷实际名 = `项目名_卷名`。若 `docker volume ls` 看不到它，说明你改过 compose 或用了不同目录结构——先核对再备份（`docker run -v` 对不存在的卷会**静默创建空卷**，备份出空 tar 还以为成功了）。

> **为什么必须停容器**：双 SQLite 已启用 WAL 模式，运行中直接复制数据文件可能拿到「主库已写、WAL 未合并」的不一致快照——**运行中复制的备份一律视为不可信**，这是刻意写死在文档里的纪律，不存在静默允许的绕过。完整备份/恢复闭环（含导入探测）是 Story 17.3 的交付物。

**恢复**：`docker compose down` → 删除并重建卷（`docker volume rm` + 新卷）→ 解包 tar 到 `/data` → `docker compose up -d`。

## 11.9 公网抢占窗口与 `EGOSYNC_TOKEN`

未预设令牌的实例，从「服务上线」到「你完成首访向导」之间存在一个**开放窗口**：任何扫到该地址的人都能抢先设置令牌，把你的实例据为己有（单用户形态没有注册体系，先到先得）。

缓解办法（compose 模板已预留）：在 `.env` 里**预设 `EGOSYNC_TOKEN`**——存在该变量时初始化向导物理关闭（`/api/setup` 返回 404），抢占面消失。公网部署一律建议预设。

即便忘预设被抢注了也不至于丢数据（数据库在你服务器上）。处理方式（容器内没有 sqlite3，借一次性 alpine 容器操作卷，效果等同「删除令牌行后重启重设」）：

```bash
docker compose stop
docker run --rm -v egosync-server_egosync-data:/data alpine sh -c \
  "apk add -q sqlite && sqlite3 /data/egosync.db \"DELETE FROM app_settings WHERE key = 'server_token_hash';\""
docker compose up -d
```

> 恢复后 `/api/setup` 重新开放，尽快完成首访向导。若不熟悉 SQL，直接整个卷重来（`docker volume rm`）也可——反正此时实例已被人占过，数据不必留。

## 11.10 桌面 → 云端迁移

**跨形态数据迁移（导出 → 导入）是后续故事（17.3）的交付物**——云端版的应用内导入/导出入口与对应端点尚未落地。当前阶段的建议：

1. 云端版从零配置使用（数据留在桌面版不动，两者本就是独立事实源——同一用户同一时刻只应有一个「在用」实例，避免双写分叉）；
2. 模型服务在云端**重新配置一遍**：设置 → 模型服务配置（与桌面操作一致，见[第 8 章](./08-Skill-MCP与模型服务.md)）；
3. **LLM API Key 无论何时迁移都不随数据走**：桌面版的 Key 存在系统钥匙串（keyring），刻意不进入任何导出包（安全边界）。云端首次使用模型服务时若密钥缺失，会收到结构化错误，按提示到 设置 → 模型服务配置 编辑对应配置重新保存密钥即可；
4. 等待 17.3 交付后，可走正式迁移：桌面版导出数据包 → 云端版导入（同格式跨形态互导），届时第 2、3 步仍适用（配置与 Key 永远手动迁移）。

## 11.11 时区（TZ）语义

时间源三分表（全应用冻结，云端桌面一致）：

| 面 | 基准 | 说明 |
| --- | --- | --- |
| 持久化 | UTC（RFC3339） | 库内时间戳一律 UTC，与容器时区无关 |
| 调度判定 | 容器 Local（`TZ`） | 晨间简报 / 周复盘的「早上 8 点」按容器时区理解——改 `TZ` 即改简报时间 |
| 前端渲染 | 浏览器时区 | 页面显示时间按你浏览器的本地时区换算 |

因此：你在东八区想早上 8 点收简报，保持默认 `TZ=Asia/Shanghai` 即可；人在海外则把 `TZ` 改成所在地时区（改完 `docker compose up -d` 生效）。注意 `TZ` 必须是合法的 zoneinfo 名称（如 `America/New_York`）——写 `GMT+8` 之类非法定义时容器会静默按 UTC 跑（简报时间就错了），可用 `docker compose exec egosync-server date` 核对容器实际时区。注意 17.2 起调度去重表含时区维度：**时区变更后的首个周期可能跳过或重复一次**（宁可一次跳过/重复也不静默双发或漏发整天——权衡见 17.2 故事）。

## 11.12 常见问题

**浏览器访问报 403（所有操作都被拒）**
通常是反代没透传 `X-Forwarded-Proto`（自有反代路径）——按 11.4 路径 B 的要求表逐项核对；确认 `EGOSYNC_BEHIND_PROXY=1` 已设置。

**`healthz` 正常但页面空白**
查看 `docker compose logs egosync-server` 是否有「API-only 模式」警告——镜像内 dist 由 `/app/static` 提供，正常不会出现；自行改动 compose 的 `EGOSYNC_STATIC_DIR` 时才会。

**opencode 提示降级**
`EGOSYNC_OPENCODE_PATH` 未设且容器 PATH 无二进制时引擎优雅降级（基础对话可用，Agent 工具不可用）。官方镜像内置 v1.15.10，正常不会出现；自定义镜像 / 自编译时核对 `docker compose exec egosync-server /app/resources/opencode --version`。

**日志里 JSON 一行一条看不懂**
这是刻意的设计（结构化日志，`docker logs` / 日志采集器直采）。关键字段：`level`（级别）、`message`（事件）、`target`（模块）；按 message 检索即可，密钥与事件 payload 永不入日志。

**证书签发失败**
80/443 端口未放行、域名解析未生效、或 80 端口被占用——`docker compose logs caddy` 会给出 ACME 具体错误。
