# 本地优先不等于绝对离线：EgoSync 如何把数据控制权交还用户

> 系列：EgoSync 与传统 AI 助手的差异（10/10）  
> 状态：当前版本能力介绍  
> 关键词：本地优先、导出、销毁、Provider、Secret Store

## 个人 AI 的数据问题更敏感

个人 AI 处理的不是几条孤立问题，而可能是工作计划、家庭安排、目标、关系和长期记忆。用户真正关心的，不只是模型回答得好不好，还包括：数据存在哪里？能不能导出？换设备时能不能迁移？不想继续使用时能不能彻底删除？

EgoSync 的答案不是一句“我们很重视隐私”，而是把控制能力做成产品功能。

## 本地优先的存储基础

当前应用使用本地 SQLite 保存主要数据，并使用独立的 conversations 数据库管理对话。数据导出服务支持 JSON、Markdown 和 SQLite 等形式，用户可以根据用途选择：JSON 适合程序化处理，Markdown 适合阅读和归档，SQLite 适合保留结构化数据。

应用还提供销毁全部数据的命令，会清空相关数据表。对于一款会沉淀长期记忆的个人工具来说，“删除”不应该只是一个隐藏的工程接口，而应当成为用户能够理解和执行的生命周期操作。

## 模型配置透明化

EgoSync 的设置页提供 Provider、模型管理和连接测试能力。密钥由 Secret Store 相关服务处理，而不是要求用户把敏感信息直接写进普通配置文件。用户可以看到自己连接的是哪个模型服务，并在需要时进行调整。

## 为什么不能说“绝对离线”

本地优先不等于所有请求都在本机完成。当用户选择云端 LLM Provider 时，为了生成回答，必要的上下文仍可能发送给对应服务商。因此更准确的产品表达是：主要数据优先保存在本地，模型调用方式由用户配置，云端调用存在明确的数据传输边界。

诚实说明边界，比使用“数据永不离开设备”这样的绝对口号更值得信任。

## 一个用户生命周期

第一次使用时配置模型 Provider并完成连接测试；日常使用中，任务、记忆和对话保存在本地；需要迁移时导出为结构化文件；决定停止使用时，从数据管理入口执行销毁。这个流程把数据从“被产品持有的副产物”，变成“由用户管理的资产”。

## 当前版本边界

导出和销毁能力需要在真实发行包中进一步做完整验证；文章展示设置页时必须隐藏 API Key 和真实 Provider 账号。不要将本地存储与完全离线运行混为一谈。

## 结语

个人 AI 的信任不是由一句隐私宣言构成的，而是由存储、配置、导出和删除等具体动作构成的。本地优先的价值，在于让用户更清楚地知道数据在哪里，也拥有把数据带走和删除的实际能力。
